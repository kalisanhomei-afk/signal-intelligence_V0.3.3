# SIGNAL｜市場定價與投資決策銜接架構 V0.1

**日期：2026-11-17｜架構設計，不是商品交易系統。** 直接在研究整合 Draft PR #24 延伸既有 K4/K5 雙假說；不新增第三條商品研究線、不新增資料庫、不接券商、不修改任何已凍結的 V0 預測，不動 `main`。

## 一、核心決策

目前最重要的技術缺口，不是再增加資料來源，而是**把「預測官方數值」與「市場定價能否因此產生機會」分開**。

例如 EIA 的淨注入量若為 +40 Bcf，不能單憑「比 SIGNAL 的 +61 Bcf 少」就推論天然氣期貨必漲；市場可能早就預估 +35、也可能受供需、季節、期限結構、其他新聞或流動性影響。

```text
K4/K5 官方來源與可追溯時點
          │
          ▼
[研究卡片] 凍結 V0／V1 → 官方結果與誤差
          │（有證據才通過）
          ▼
[預期差] 與當時可用的市場共識比較
          │（共識來源、發布與取得 UTC、版本）
          ▼
[金融標的] 確認真正可比的契約與行情口徑
          │（交易所、標的、契約月份、報價單位、換月）
          ▼
[價格反應] 預期差與價格、波動、交易成本的實證關係
          │（公告前後相同契約、可查的價格快照、樣本外）
          ▼
[風險預算] 保證金、流動性、相關性、最大曝險
          │（歷史壓力情境、持倉和許可）
          ▼
[投資決策] 明確 Go／No-Go；現階段一律 No-Go
```

這個銜接層**只承接既有研究卡片**，不從網路重新讀取、不自己產出預測，不把事後結果混進事前資料。

## 二、五道關卡與責任

| Gate | 需要的證據 | 現在 K4／K5 | 接下來的工作 |
|---|---|---|---|
| G1 公告前市場預期 | 指定事件、單位一致的具名事前共識、來源版本、可核實發布／取得 UTC | **BLOCKED** | 按現有排程持續保存，不以日曆 +69 Bcf 偽稱共識 |
| G2 可交易標的映射 | 交易所、商品／到期月、合約乘數、報價單位、結算及換月方法 | **BLOCKED** | 確認是否選擇期貨、ETF 或其他工具，必須有正式條款與資料權限 |
| G3 市場價格證據 | 同一合約公告前後行情、雙向報價與取得時間、來源權限、缺漏與異常處理 | **BLOCKED** | 先做零成本來源可行性審查；不足時暫停 |
| G4 可重現價格關係 | 事件預期差、價格反應、樣本外週期、成本後效益與反證 | **BLOCKED** | 不在首次一筆事件中宣稱 alpha |
| G5 投資組合風險 | 費用／滑價、保證金、流動性、相關曝險、持倉限制及人工核准 | **BLOCKED** | 不接任何真實帳戶或交易執行 |

即使 11/20 K5 成功計算官方淨變動對 V0 的誤差，也只代表 K5 的**研究事件驗收**完成，**不會自動解除上述五道投資關卡**。

## 三、最小可交付架構

**本次新增**：

- `research_overview/market_decision_bridge.json`：兩個已存在的假說如何向下游連接預期差、商品映射、行情、價格反應及風險。未取得者一律 `null`，而不是零。
- `research_overview/decision_bridge.py`：僅使用 Python 標準函式庫；從共用研究卡片核對假說 ID／事件／單位，確認五道關卡都尚未放行，輸出缺口清單及 `NO_GO_DESIGN_ONLY`。
- `research_overview/tests/test_decision_bridge.py`：測試「虛構市場共識、價格、到期契約、樣本外 alpha、持倉」不得誤進入投資決策。
- 共用總覽加入 **第五部分：市場定價與投資決策銜接**，顯示哪一道關卡沒有證據。這是架構視圖，不是行情頁。

**不做**：建新的 ETL 框架、第二套資料庫、即時 websocket、LLM 自動下單、每天調整模型數字、與未經授權的交易帳戶連結。

## 四、後續導入時才須擴充的欄位

後續的 G1–G5 實作應分別建立獨立、可稽核的 evidence 文件，綁定研究假說 ID、`event_id`、來源原始內容 SHA、取得 UTC、證據品質與對應 Git commit；不能直接把數值塞進畫面上完成狀態。

- **G1**：`model_forecast - consensus` 是*事前預期差*，不是實際公告 surprise。後者為 `actual - consensus`，只能在真正公告後計算；如果共識不存在，就兩者都必須為 `null`。
- **G2**：標的映射不能只有「玉米」或「天然氣」。應指明期貨／ETF 的標的和合約、日期、報價單位、合約規格、roll 規則；商品報告單位與期貨價量單位不可直接相減。
- **G3**：市場價格需指明資料提供者、可使用的授權、合約、`quote_time_utc` 和取得時間。公告前快照必須早於正式公布，公告後快照必須在公布後，不能用日終結算價冒充公告瞬間的可成交價格。
- **G4**：區分因果敘事、統計相關、事前可交易預測；避免事件發布後挑選最佳觀察窗，需事先固定價格反應觀察窗與樣本外評估方法；納入買賣價差、滑價與費用，不能把最有利價格當真實成交。
- **G5**：即使 G1–G4 成功也只足以產生「風險審查候選」，應檢查相關曝險、槓桿、保證金追加、壓力測試、流動性與回撤；必須有明確授權，才能將來另開交易開發 PR。

**型別約束**：未驗證為 `null`／`NOT_VERIFIED`，絕不可用 0 偽裝有預測。美元／蒲式耳、Bcf、MMBtu、價格百分比、帳戶貨幣及契約乘數是不同單位；任何轉換都應有單位來源與日期。

## 五、實施順序與停止條件

1. **現在**：將這份設計、兩個 `NO_GO` 來源卡、驗證測試及只讀介面完成於 PR #24；資料不合格時程式必須失敗。
2. **11 月 19–20 日 K5 事件驗收後**：只更新研究的官方結果及一次性共同卡片。不能因 V0 這次較準，就提前放行交易設計。
3. **12 月 WASDE 之後**：將 K4 的事前／事後官方結果依相同契約整理，再比較是否有足夠事件樣本推動 G1。
4. **資料權限、共識與連續來源均可靠時**：才另行提出 G2／G3 的最小實驗與相對成本，而不是在本 PR 實作行情獲取。
5. **如果 G1 市場預期資料長期不可驗證、G3 報價成本不合理或 G4 不優於簡單基準**：停止該策略而非繼續追加 Agent 和功能。

### 多 Agent 分工（沿用現有工具，不另建平台）

資料 Agent 蒐集原始證據及時間版本；研究 Agent 建立機制及可反證的預測；PIT／QA Agent 驗證來源、單位、前後時序與反證；最後由整合 Agent 產生共用總覽和阻塞原因。任何 Agent **沒有**直接提升交易權限的能力。

**本階段可驗收的成果，是一個無法誤把研究進度認作可交易策略的架構接口，而不是一套尚無資料的自動交易系統。**
