# 視界 SIGNAL V0.4.3｜來源覆蓋稽核與資訊盲區診斷

## 這次實際增加的能力
V0.4.2 的 GitHub Actions 已成功取得 **11 項候選中的 4 項 arXiv 作者摘要元資料（M0A）**，並報告 API 錯誤 0；這**不代表論文主張已經查證**，也不能推論全球重大新聞的覆蓋率。

V0.4.3 加入可以隨每次 Github Actions 自動運作的**來源覆蓋診斷引擎**：
- 將 4 條 RSS 視為 3 家獨立發布機構，不重複計算 arXiv 兩條頻道。
- 區分「有已審核來源提供相關資料」與「目前沒有正式資料來源」，列出經濟、科技研究、全球政治、產業、能源、台灣、日本、巴西、社會等 10 個觀察面向。
- 自動顯示來源領域的盲區、各發布機構最新項目日期及來源最後成功採集時間；不將新聞發佈稀疏誤判成系統故障。
- 允許往後建立人工檢核的重大事件參考基準；**基準為空時，不計算全球重要事件遺漏率**。
- 以網站發布護欄拒絕「虛構全球覆蓋率、虛構已查證數字、偽造重要性評分」等錯誤資料。
- 不改動 M0／M0A 的證據層級；不新增任何未經授權的資料採集；保留黑金介面，將「情報來源覆蓋與盲區」加入既有「證據檢核」頁面下方。

## 更新到現有 GitHub（不用建立新 Repository）
1. 在 GitHub Desktop **Fetch origin → Pull origin** 同步自動資料更新。有衝突就先停止，不要 Force Push。
2. 解壓縮 `視界_SIGNAL_V0.4.3_來源覆蓋與盲區診斷_覆蓋更新包.zip`，將**資料夾內的內容**複製到現有的 Repository 根目錄。確認 `.github` 與 `index.html` 位於根目錄，不多包一層資料夾。
3. **請勿刪除** `.git`、`data/live_items.json`、`data/evidence_enriched.json`、`data/intelligence.json` 等已蒐集紀錄。覆蓋包本身不包含它們。
4. GitHub Desktop：Summary 輸入 `Add V0.4.3 source coverage and blind-spot audit` → **Commit to main** → **Push origin**。若遠端先有更新，再 Fetch／Pull 後推送。
5. GitHub → **Actions** → **SIGNAL V0.4.3 source coverage audit + Pages** → **Run workflow** → `main` → Run workflow。
6. 驗收 `collect-build` 與 `deploy` 均為綠燈，並檢查執行摘要多了「**V0.4.3｜情報來源覆蓋與盲區驗收**」。
7. 開啟原本 SIGNAL 網站 → **證據檢核**，下方應看到新的「**情報來源覆蓋與盲區**」區域；目前來源偏向 Fed、BEA、arXiv，因此全球政治、產業、台灣等仍應顯示盲區。

## 必須通過的 5 個驗收關卡
- [ ] V0.4.2 的 M0A／M0 分級不變；不會將作者摘要變成獨立查證。
- [ ] 來源由四條頻道計為三家獨立機構，且沒有把「多家機構」等同「同一主張的獨立證據」。
- [ ] 未建立人工事件基準時，「全球事件遺漏率」顯示 **—／不可量測**，而不是 0%、100% 或某個猜測分數。
- [ ] 「已驗證主張」仍是 **0**；所有來源不足處皆可見，不自動補寫未知消息。
- [ ] GitHub Actions 完成後，`data/source_quality_v043.json` 會被產生及安全發布；既有資料保留。

## 技術與資料限制
- 這個版本先診斷**資料來源覆蓋空缺**，**尚未實際新增國際政治／產業來源**，也不會搜尋來源以外的全球事件。
- 來源的合法使用與獨立查證，仍需要逐家完成。我們已保存前期 37 家候選來源評估，不因目前只有四條 RSS 就取消它們。
- `data/quality_reference_events.json` 初始為空；人工事件基準只保存可公開的原始鏈結與核對紀錄，不得加入私人資料。
- 無需 OpenAI API Key，本版只對已蒐集元資料進行**可審計的覆蓋診斷**，不提供投資建議與行情預測。

## 下一個真正有內容的交付
V0.4.4 不是再做管理頁面，而是根據盲區報告優先啟用不同地區及專業領域的合規來源，並建立最少 20 筆**由人工選定、獨立於系統擷取來源的事件基準**。確認跨類別漏報與來源偏向後，進入 V0.5 每日／每週情報生成。
