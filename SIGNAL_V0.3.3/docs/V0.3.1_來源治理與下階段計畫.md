# 視界 SIGNAL｜V0.3.1 資訊來源治理、品質驗收與開發路線

**版本：V0.3.1｜2026-11-05**　　**狀態：候選來源庫已建立，尚非正式授權清單**

## 一、開發決策：先把來源制度做對，再擴充自動蒐集

SIGNAL 的目標不是新聞量最大，而是讓讀者快速知道：（A）世界重大變化，（B）科技與新知識，（C）產業與新商業模式，（D）重要事件事前預告。每則重要主張須顯示原始證據、證據型別、限制與後續驗證方向。

**本次新增：37 個互相區分的發布機構候選來源**，存放 `data/source_registry.json`，並建立 `source_registry.csv`、`source_audit.json`、`scripts/audit_sources.py`、`scripts/test_governance.py`。原先 10 條 RSS 頻道來自 **6 個發布機構**（BBC 4 條、arXiv 2 條，其餘各 1）。**37 個候選機構 ≠ 37 個已接入來源。**

**目前狀態：** 37 個為來源治理候選；10 條先前頻道保留作 V0.3 技術試驗，授權及連網檢查尚未全部完成。**目前正式生產核准數量：0；不宣稱可合法自動取得所有候選機構的文章。**

### 來源的角色必須分開

| 來源層 | 用途 | 不能直接推論的事情 |
|---|---|---|
| 官方統計、公告與公司申報 | 確定官方發布內容、時間、定義、數值 | 官方立場或企業宣稱就是獨立證實的事實 |
| 國際新聞與專業財經報導 | 重大新聞、獨立採訪、補充脈絡 | 轉載三次就等於三次獨立驗證 |
| 同儕審查研究／專業科技編採 | 科學及技術證據與背景 | 所有刊物文章都經同儕審查；研究已能量產 |
| 預印本／開源／產品與開發者社群 | 早期發現研究、工具、產品與應用 | 熱度、星數、募資或展示等於產品可靠／商業獲利 |
| 付費產業研究 | 分析庫存、需求、資本支出、供應鏈 | 研究機構預測就是事實；訂閱費等於合法再製授權 |

## 二、六維來源審核（不同於個別新聞可信度）

對**發布機構**審查以下六項，使用「有證據／部分有／缺資料／不適用」，不以缺乏證據的單一百分制分數假裝精確：

1. **可信度**：原始紀錄、方法學、編輯程序、同行評審、更正政策；每種來源適用的證據不同。
2. **獨立性**：出資、新聞採訪、廣告與贊助、研究者利益、報導是否來自相同原始消息。
3. **專業性**：能否提供非泛泛而談的領域知識，以及可檢驗的技術細節。
4. **前瞻性**：是否能提早發現重要轉變；**新**不能自動升級為**已證實**。
5. **覆蓋完整性**：地理、語言、產業、企業大小、研究成熟度、觀點及資訊類型。
6. **合法可取得性**：公開可閱讀與允許程式化保存／生成摘要／轉載／衍生數據**逐一區分**，包括資料頻率及計費。

**核心原則**：評價來源的「角色與適用範圍」，而不是只列一份聲望排行。每篇事件要獨立記錄其證據：`官方原始紀錄 / 一手採訪 / 學術研究 / 企業自述 / 專業評論 / 社群訊號`。

## 三、候選來源範圍

來源庫包含：

- **總體／官方／公司揭露**：Fed、BLS、BEA、SEC、TWSE/MOPS、台灣央行、ECB、BOJ、BIS、IMF、IEA、EIA、巴西央行、IBGE、OECD。
- **國際與金融編採**：Reuters、AP、BBC、Financial Times、Bloomberg、Nikkei Asia、The Economist。
- **頂尖科學及工程**：Nature、Science、IEEE Spectrum、MIT Technology Review、Quanta、arXiv、ACM Digital Library、NASA JPL。
- **早期技術／商業訊號**：GitHub、Hacker News、Product Hunt、TechCrunch、SemiAnalysis、TrendForce、PitchBook。

**這些只是候選，不是自動全部啟用。** 各機構的完整逐列優勢、風險、接入模式、授權注意事項及官方／主站連結，見 `data/source_registry.csv` 和交付的 XLSX。

## 四、優先接入策略（不是依免費排序）

| 階段 | 先納入哪些 | 驗收重點 |
|---|---|---|
| G1-A：授權與格式 | Fed、BLS、BEA、SEC、TWSE、arXiv、GitHub 等 **資料第一手或公開 API** | 逐端點核對 Terms、API 使用限制、更新頻率、標題與連結的允許使用範圍，實際連線通過後再放行 |
| G1-B：獨立核對 | Reuters、AP、FT、BBC、Nikkei 等 **編採來源** | 使用可合法接入的標題／連結／授權 API；至少兩個**原始消息來源**而不是重複轉載 |
| G1-C：科技新訊 | Nature、IEEE Spectrum、Quanta、arXiv、GitHub／Hacker News | 分開標示 peer-reviewed、preprint、產品宣稱、開源專案；每週人工抽樣核查 |
| G1-D：產業及投資 | IEA、TrendForce、SemiAnalysis、彙整財報及市場資料 | 付費資訊僅在驗證**不可替代價值**且具合法授權後接入；避免付費資訊變成不可追溯黑盒 |

**優先次序並非聲稱其他來源不可靠**；實務上由權利、格式穩定性、經濟重要性與覆蓋缺口決定。

## 五、來源治理狀態機（不能由新增 RSS URL 直接跳到啟用）

`候選 → 來源角色審查 → 取得方式與授權核對 → 實際連網／格式測試 → 小樣本獨立查核 → 核准自動發現 → 週期性稽核`。

`source_registry.json` 為**發布機構層**；`sources.json` 為**蒐集頻道層**。同機構的 4 條 RSS 不能視為 4 個獨立資訊來源。

- 稽核腳本：`python scripts/audit_sources.py --output data/source_audit.json`（離線可執行）。
- 回歸測試：`python scripts/test_governance.py` + `python scripts/test_pipeline.py`。
- `python scripts/refresh.py --production`：未取得來源授權審核、啟用核准、連網測試者**拒絕進入正式模式**。
- 原 V0.3 的 10 個頻道保留 `legacy_pilot` 狀態；**任何新頻道不能冒用 legacy_pilot 繞過審核**。
- 來源網站提供公開 RSS，不等於授權把整篇新聞輸入模型、保存全文或公開再發行。系統仍只擷取標題、連結、時間與來源；未審核的標題不進每日精選。

## 六、衡量資訊品質：同時測量「選對」與「漏掉」

正式驗收（初步設計門檻，**目前均未達成或未測量**）：

| 指標 | 定義 | 建議門檻 |
|---|---|---|
| 來源追溯率 | 重要情報可追溯原始URL與發布日期 | 100% |
| 來源權利紀錄 | 每條正式啟用頻道具權利審核、資料格式及測試紀錄 | 100% |
| 重大事件召回率 | 系統找出人工基準清單重大事件的比例 | 先以 ≥85% 作實驗目標；至少 14 天評估 |
| 主張型別標示 | 重大主張標明事實、研究、預測或企業宣稱 | ≥95%（抽樣審核） |
| 獨立交叉核對 | 重要且有爭議的主張能追到不同原始採訪／文件 | 設定例外原因並稽核；不能只計新聞家數 |
| 同溫層防護 | 至少涵蓋官方、編採、科技研究、早期訊號；地區不限美歐 | 每週查看地區/主題分布與「遺漏事件」 |
| 推薦品質 | 每週手動標註「值得讀」「噪音」「錯誤」「應該納入但漏掉」 | 連續四週調整，保留對照組 |

避免將「台灣／美國／巴西」等地區配額當成政治價值判斷；此為資訊覆蓋的地理分布監測，不對政治人物與觀點做優劣排名。

## 九、本次來源審核的實證補充與預設封鎖（2026-11-05）

本次逐項查閱了若干官方編輯與 API 條款，並更新 `視界_SIGNAL_V0.3.1_37家資訊來源評估.xlsx` 的「官方條款核對」頁。此頁是**具體條款的初步查核紀錄**，不是 37 家的完整授權審定。以下事項必須作為接入時的檢查表：

- Reuters 與 AP 的編輯規範可用來了解其編採制度，**不代表**其他媒體轉載它們就形成第二個獨立來源，也不代表取得全文機器處理權。參閱 https://reutersagency.com/about/our-trust-principles/ 與 https://www.ap.org/about/news-values-and-principles/ 。
- SEC EDGAR 公開資料雖可以程式讀取，但必須遵守現行公平使用指引與 User-Agent 識別，現行上限為每秒 **10 次請求**，實作應遠低於上限以留足餘裕。參閱 https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data 。
- BEA API **需要申請 UserID**；參閱 https://apps.bea.gov/API/docs/ 。台灣證交所 OpenAPI 提供開放資料介面，但資料集、授權與 MOPS 涵蓋範圍需逐端點分別核查。參閱 https://openapi.twse.com.tw/ 。
- arXiv 提供 RSS／Atom，且須遵守 API 使用條款；`預印本 / 同儕審查 / 獨立重現 / 商業部署` 不能混成一種。參閱 https://github.com/arXiv/arxiv-docs/blob/develop/source/help/rss.md 。
- Product Hunt API **預設不得用於商業用途**，若未來公開營運需另取得同意。參閱 https://api.producthunt.com/v2/docs 。
- IEA 對資料重製、衍生模型及定期／營利性衍生資料服務有額外權利限制；取得個人訂閱不自動取得衍生商業產品授權。參閱 https://www.iea.org/help-centre/usage-and-rights 。
- FRED（目前**未計入37候選**）未來可成為價格／經濟資料匯集候選，但 API 要求金鑰且個別時間序列可能包含第三方版權，投資研究不可忽視逐系列權利。參閱 https://fred.stlouisfed.org/docs/api/terms_of_use.html 。

**本版執行層防護新增：** 每個發布機構與每條頻道皆須有 `permission_evidence_url`（權利依據）、`permission_checked_at`、`approved_by`、`approved_use_scope`；頻道另外需要 `live_tested_at` 與 `live_verified`。單純將 `status` 改為 `approved` 不能通過正式模式稽核。這是最低限度的人工作業證據要求，程式不能自動判定法律授權有效性。來源更新任務的 GitHub Actions 預設停用，需在平台設定 `SIGNAL_PRODUCTION_ENABLED=true` 且通過 `--production` 權利閘門才允許自動抓取。**當前沒有任何頻道被核准，所以不應打開這個開關。**

## 十、現階段保留的覆蓋缺口與採購決策

1. **獨立性缺口：** 國際英文媒體偏重，歐洲與美洲跨媒體同源報導較多；未來需補充亞洲本地、印度、非洲與拉丁美洲的可靠第一手來源，而非機械地設定政治觀點配額。
2. **專業性缺口：** 醫療、生物製造、先進材料、農業、水資源、地緣產業政策等尚沒有足夠專題來源；初版用跨領域週報探索，驗收後才新增專門資料源。
3. **付費採購原則：** 先用公開資料建立 14 天人工基準清單（重大新聞召回、技術早期訊號有效率、重複報導）；只有當特定付費來源**明確補足未覆蓋的重要事件，且准許我們的使用情境**才提出授權採購。不能以免費取代品質，也不能以付費推定品質。
4. **投資系統隔離：** 日後新聞資訊與財經資產價格，採用不同資料權限、時點版本與稽核流程；新聞來源的「高可信」標籤，不等於對 15～30 日行情具預測能力。
