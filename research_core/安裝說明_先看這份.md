# 視界 SIGNAL K2｜雙引擎（正向情境 × 反向研究）離線驗收

**版本性質：K2 可執行增量包，接續 K1，不會修改正式網站或 GitHub Actions。**

## 1. 安裝前

請先確認 K1 已存在於開發分支 `signal-evidence-rebuild` 的 `research_core` 目錄。本 K2 必須依賴 K1 的 `contracts.py`、`asof_guard.py`、`stockflow.py` 和 `fixtures/synthetic_corn_vintages.json`。

本包**只包含 `research_core/k2` 新資料夾**，不是整份 K1 的覆蓋更新。不用重新安裝 K1。

## 2. 安裝（Windows／GitHub Desktop）

1. 在 GitHub Desktop 確認 Current repository 為 `signal-intelligence_V0.3.3`，Current branch 為 **`signal-evidence-rebuild`**。如果有未完成變更，先釐清再操作。
2. 選 **Repository → Show in Explorer**，打開真正的 Repository 根目錄。
3. 解壓縮本 ZIP。可見 `research_core/k2`。進入解壓縮後的 `research_core`，**只複製 `k2` 資料夾**，貼到 Repository 原有 `research_core` 資料夾裡。
4. 核對路徑 `Repository/research_core/k2/engine.py` 和 `Repository/research_core/k2/tests/test_engine.py`。**不要把 `research_core` 整個資料夾貼上去取代既有 K1，也不要把 k2 放在 Repository 根目錄。**
5. GitHub Desktop 的 Changes 應只出現 `research_core/k2/...` 新檔案。若 `.github/workflows`、原本 `research_core/contracts.py` 或 `rebuild_r8` 被修改，先不要 Commit。
6. R6、R8-B 的 API 授權保持 `NO`；這次不會改它們。
7. Summary：`Add SIGNAL K2 offline dual engine what-if and reverse diagnosis`
8. 選 **Commit to signal-evidence-rebuild → Push origin**。不要建立 PR，不要合併 `main`。

## 3. 驗收

可直接開啟 `research_core/k2/out/k2_review.html` 閱讀**這份打包環境的**黑金報告。真正要在自己電腦重跑，請安裝 Python 3.11+，在 Repository 根目錄輸入：

```powershell
py -3 -m unittest discover -s research_core/tests -v
py -3 -m unittest discover -s research_core/k2/tests -v
py -3 -m research_core.k2.demo
```

或雙擊 `research_core/k2/執行K2離線驗收.bat`（這個批次檔只執行 K2 測試）。

K1 回歸在打包環境實測 **80 項通過**；K2 新增 **42 項通過**。這些只是工程測試，沒有實際 USDA 或價格預測資料。

## 4. K2 的能力與界線

- **引擎 B（正向）**：對指定時間點可用的合成玉米供需數據，進行假設性產量、進出口、需求衝擊，計算期末庫存變化；拒絕直接更改期末庫存。
- **引擎 A（反向）**：在後續修訂已被取得之後，拆解期末庫存變化的**會計貢獻**，保留多種可能的上游原因，全部標示未驗證。
- **閉環**：比較「原先凍結的假設情境」與「後續已觀測修訂」，紀錄差額；不能把後續資料偷放回過去。
- **限制**：沒有因果識別、真實市場價格、預測機率、資產配置或交易。不能用此測試結果推論期貨漲跌。

## 5. 下一道開發門檻

K2 通過後，K3 必須使用**發布時點清楚的真實官方歷史資料與多期測試**，與簡單基準比較。不能把單一虛構例子說成「預測準確」或「可以獲利」。
